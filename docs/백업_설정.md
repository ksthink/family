# 🔐 Google Drive 백업 설정 가이드

원본 미디어와 데이터베이스를 **암호화된 상태로** Google Drive에 백업합니다.

> **가장 중요한 원칙**
> 암호화 비밀번호를 잃어버리면 **백업 전체를 복원할 수 없습니다.**
> 서버 밖(종이 또는 패스워드 매니저)에 반드시 따로 보관하세요.

---

## 1. 사전 확인

### 용량 계산

| 자료 | 대략 용량 | 비고 |
| --- | --- | --- |
| 사진 1,000장 | 3~5GB | 스마트폰 원본 기준 |
| 음성 100시간 | 5~10GB | WAV 원본 |
| 영상 10시간 | 20~60GB | 원본 무편집 |

무료 15GB는 금방 찹니다. **Google One 100GB~2TB** 요금제를 먼저 확인하세요.
이미 구독 중이라면 추가 비용 없이 시작할 수 있습니다.

### 왜 암호화가 필요한가

가족의 목소리와 사적인 기록을 남의 서버에 평문으로 두지 않기 위해서입니다.
rclone `crypt`를 쓰면 **파일 내용은 물론 파일명까지** 암호화되어 올라갑니다.
Google 쪽에서는 의미를 알 수 없는 파일 목록만 보입니다.

## 2. rclone 설치 및 인증

Google 인증에는 브라우저가 필요한데 서버는 헤드리스입니다.
**PC에서 인증을 마치고 설정 파일만 서버로 복사**하는 방식으로 처리합니다.

### ① PC에서 (Windows/Mac)

rclone을 설치하고 터미널에서:

```bash
rclone config
```

**Google Drive 리모트 만들기**

| 항목 | 입력 |
| --- | --- |
| `n` (New remote) | 새로 만들기 |
| name | `gdrive` |
| Storage | `drive` (Google Drive) |
| client_id / client_secret | 비워둠 (Enter) |
| scope | `1` (Full access) |
| root_folder_id | 비워둠 |
| Edit advanced config | `n` |
| Use auto config | `y` → 브라우저가 열리면 구글 로그인 및 허용 |
| Configure as Shared Drive | `n` |

### ② 암호화 리모트 덧씌우기

같은 `rclone config` 안에서 다시 `n`:

| 항목 | 입력 |
| --- | --- |
| name | `gdrive-crypt` |
| Storage | `crypt` |
| remote | `gdrive:family-archive-encrypted` |
| filename_encryption | `1` (standard) |
| directory_name_encryption | `1` (true) |
| password | **직접 입력** (자동생성 대신 기억 가능한 강한 암호) |
| password2 (salt) | 비워두거나 별도 입력 |

> 📝 여기서 입력한 **password와 salt를 지금 바로 종이에 적어두세요.**
> 이 값 없이는 백업 데이터를 영원히 열 수 없습니다.

### ③ 서버로 설정 복사

PC에서 설정 파일 위치 확인:

```bash
rclone config file
```

그 파일을 서버로 복사합니다:

```bash
# PC에서 실행
scp ~/.config/rclone/rclone.conf 사용자명@서버주소:~/.config/rclone/
```

서버에서 권한을 잠급니다:

```bash
chmod 600 ~/.config/rclone/rclone.conf
```

### ④ 서버에서 확인

```bash
rclone lsd gdrive-crypt:
```

오류 없이 끝나면 성공입니다.

## 3. 백업 스크립트 설치

```bash
# 저장소의 scripts/ 를 서버에 배치
sudo cp scripts/backup.sh scripts/restore.sh /usr/local/bin/
sudo chmod +x /usr/local/bin/backup.sh /usr/local/bin/restore.sh
```

### 환경에 맞게 값 조정

스크립트 상단 변수를 확인하세요. 기본값과 다르면 `/etc/default/family-archive` 에 넣고
cron에서 읽어오도록 하는 편이 깔끔합니다.

```bash
sudo tee /etc/default/family-archive > /dev/null << 'EOF'
DATA_DIR=/data
REMOTE=gdrive-crypt
REMOTE_BASE=family-archive
PG_CONTAINER=family-archive-db
PG_USER=archive
PG_DB=family_archive
EOF
```

### 수동 실행 테스트

```bash
sudo backup.sh db      # DB만 먼저 시험
sudo backup.sh full    # 전체
```

---

## 4. 자동 실행 (cron)

```bash
sudo crontab -e
```

```cron
# Family Archive 백업
# DB 덤프: 하루 3회 (점심·저녁·새벽)
0 13,21 * * *  . /etc/default/family-archive; /usr/local/bin/backup.sh db  >> /data/logs/cron.log 2>&1

# 전체 백업: 매일 새벽 3시 (DB + 원본 미디어 + 정리)
0 3 * * *      . /etc/default/family-archive; /usr/local/bin/backup.sh full >> /data/logs/cron.log 2>&1

# 백업 검증: 매월 1일 새벽 4시
0 4 1 * *      . /etc/default/family-archive; /usr/local/bin/restore.sh verify >> /data/logs/verify.log 2>&1
```

> 미디어는 새 파일이 생기는 즉시 올리고 싶다면, 업로드 API에서 처리 완료 후
> `backup.sh media` 를 백그라운드로 호출하는 방식도 가능합니다.

## 5. 복원 방법

### 백업 목록 확인
```bash
restore.sh list
```

### DB 복원
```bash
restore.sh db db_20260315_0300.sql.gz
```

### 원본 미디어 복원
```bash
restore.sh media /data/raw_archives
```

### 서버가 완전히 망가졌을 때

1. 새 서버에 Ubuntu Server + Docker 설치
2. PC에서 `rclone.conf` 복사 (또는 rclone config로 재설정 — **암호화 비밀번호 필요**)
3. `restore.sh media /data/raw_archives` 로 원본 회수
4. Docker Compose로 DB 컨테이너 기동
5. `restore.sh db <최신덤프>` 로 데이터베이스 복원

`derived/`(썸네일·분할 클립)와 `exports/`는 백업하지 않습니다. 원본과 DB에서 재생성됩니다.

## 6. 월 1회 점검 항목

- [ ] `restore.sh verify` 결과 확인 (자동 실행되지만 로그는 직접 볼 것)
- [ ] Google Drive 잔여 용량 확인
- [ ] `/data/logs/backup.log` 에서 실패 기록 확인
- [ ] 암호화 비밀번호 보관 상태 확인

### 자주 겪는 문제

**`rclone` 인증 만료**
장기간 미사용 시 토큰이 만료될 수 있습니다. PC에서 `rclone config reconnect gdrive:` 후
설정 파일을 다시 복사하세요.

**업로드가 느리거나 중단됨**
Google Drive는 하루 업로드 용량에 제한이 있습니다. 초기 대량 업로드는
며칠에 나눠 진행하거나 `--bwlimit` 옵션으로 속도를 조절하세요.

**"파일이 이미 있습니다" 경고**
`copy`는 동일 파일을 건너뛰므로 정상입니다. 중복 업로드가 아닙니다.

---

## 7. 왜 이렇게 설계했는가

| 결정 | 이유 |
| --- | --- |
| `sync`가 아닌 `copy` 사용 | 로컬에서 실수로 파일을 지워도 **원격 백업은 살아남습니다** |
| `derived/`, `exports/` 제외 | 원본과 DB에서 재생성 가능. 용량과 업로드 시간 절약 |
| DB는 하루 3회, 미디어는 1회 | DB는 작고 자주 변하며, 미디어는 크고 한 번 올리면 안 바뀜 |
| 임시 DB에 복원해 검증 | 운영 DB를 건드리지 않고 백업이 살아있는지 확인 |
| 로컬 덤프 30개 보관 | 원격 장애 시에도 최근 데이터는 손에 남아 있음 |
