# 🗃 자료 분류체계

업로드한 자료를 어떤 기준으로 나눌 것인가를 정리한 문서입니다.
국내 지역·공동체 아카이브의 형태분류 관행과 DACS의 문헌형식(documentary form) 개념을 참조했습니다.

---

## 1. 왜 축을 나누는가

`media_type`(파일 형식)만으로는 부족합니다.

> **스캔한 편지**는 파일로는 이미지지만, 자료로는 **편지**입니다.
> "1962년 혼인신고서를 찍은 사진"과 "1985년 나들이 사진"은 둘 다 `image`지만 성격이 완전히 다릅니다.

국내 아카이브들도 분류를 하나로 합치지 않습니다. 출처·주제·시기·형태를 각각 별도 축으로 두고, 형태분류만 문서류·사진류·시청각류 등으로 나눕니다. 본 시스템은 이를 참고하되 규모에 맞게 **네 개 축**으로 단순화합니다.

| 축 | 필드 | 무엇을 구분하나 | 입력 |
| --- | --- | --- | --- |
| **형태** | `media_type` | 파일이 무엇인가 (text/image/video/audio) | 자동 |
| **문헌형식** | `doc_type` | 자료의 성격이 무엇인가 (편지·증명서·일기…) | 자동 추정 + 수정 |
| **출처** | `creator_id` | 누가 만들었나 | 업로드 시 |
| **시기** | `recorded_at` | 언제 만들어졌나 | EXIF 자동 + 수정 |

> 주제 축은 별도로 두지 않습니다. 태그와 의미 검색(pgvector)이 그 역할을 대신합니다.

## 2. 문헌형식 분류 (`doc_type`)

분류 기준은 **"AI 학습에 어떻게 쓰이는가"**입니다. 아카이브 브라우징에도 유용하고, Export 로직이 여기서 자동으로 갈립니다.

### A. 자기표현 — 본인의 말과 생각

LLM 파인튜닝의 핵심 자료입니다. 말투·어휘·사고방식이 담깁니다.

| 코드 | 이름 | 포함 |
| --- | --- | --- |
| `diary` | 일기·수첩 | 일기장, 다이어리, 메모 수첩, 가계부의 소회 부분 |
| `letter_sent` | 보낸 편지 | 본인이 쓴 편지·엽서·연하장 (사본 또는 미발송분) |
| `writing` | 수기·회고·자유글 | 회고록 초고, 시·수필, 낙서, 유서, 카톡·문자 |
| `interview` | 인터뷰 답변 | 데일리 인터뷰 녹음/텍스트, 구술 채록 |
| `oral_history` | 구술 | 대화 녹음, 옛날 이야기, 노래 |

### B. 증빙 — 사실을 확정하는 자료

말투는 없지만 **생애 연표를 정확하게 만들어줍니다.** 혼인신고서 하나가 결혼 연도를 확정하고, 그것이 다른 기록들의 시점 추정 기준이 됩니다. RAG에서 "언제 결혼하셨지?"에 정확히 답하는 근거이기도 합니다.

| 코드 | 이름 | 포함 |
| --- | --- | --- |
| `vital` | 신분·가족관계 | 제적등본, 가족관계증명서, 혼인·출생·사망 신고서, 주민등록 |
| `education` | 학적 | 졸업장, 성적표, 학생증, 통지표, 학적부 |
| `award` | 상장·표창 | 상장, 감사패, 자격증, 면허증, 임명장 |
| `official` | 행정·법률 | 계약서, 등기부, 판결문, 병적증명, 각종 통지서 |
| `financial` | 금융·재산 | 통장, 영수증, 세금 자료, 보험증서, 가계부의 수치 부분 |
| `medical` | 의료 | 진단서, 처방전, 건강검진 결과, 예방접종 기록 |

> ⚠️ 이 계열은 **민감정보를 포함할 가능성이 높습니다.** 5절 참조.

### C. 타인 생산 — 남이 그 사람에 대해 남긴 것

`creator_id`가 본인이 아닌 자료입니다. RAG에는 유용하지만 **페르소나 학습에는 쓰지 않습니다.**

| 코드 | 이름 | 포함 |
| --- | --- | --- |
| `letter_recv` | 받은 편지 | 받은 편지·엽서·카드, 조문 방명록 |
| `media` | 간행물 등장 | 신문 기사, 사보, 동창회보, 지역 소식지 |
| `about` | 타인의 기록 | 가족이 쓴 회고, 추도사, 타인의 일기 속 언급 |

### D. 생활 기록 — 삶의 장면

| 코드 | 이름 | 포함 |
| --- | --- | --- |
| `photo` | 사진 | 인물·가족·풍경 사진, 앨범 |
| `av` | 영상·음성 | 홈비디오, 행사 촬영, 녹음테이프 |
| `ephemera` | 소품 | 입장권, 영수증, 명함, 청첩장, 프로그램, 배지 |
| `object` | 박물류 | 애장품, 도구, 의류, 트로피 등 실물 |

> **`ephemera`를 빼지 마십시오.** 내용이 전혀 없는 놀이동산 입장권 한 장이 그날의 기억을 통째로 불러오는 경우가 있습니다. 국내 공동체 아카이브에서도 종이 기록보다 시청각류·박물류가 훨씬 많이 수집되는 경향이 보고됩니다. **회상 유도용으로는 가장 강력한 자료일 수 있습니다.**

### E. 한국 가정 특수 유형

| 코드 | 이름 | 포함 |
| --- | --- | --- |
| `genealogy` | 족보·가계 | 족보, 가승, 항렬표, 가계도 |
| `ritual` | 의례 | 제사 축문, 지방, 혼례·상례 기록, 부의록, 예단 목록 |

> 고령 구성원의 아카이브에서 실제로 자주 나오는 유형이며, 다른 분류에 억지로 밀어넣으면 검색이 어려워집니다.

## 3. 전체 코드 일람 (20종)

```
자기표현 : diary  letter_sent  writing  interview  oral_history
증빙     : vital  education  award  official  financial  medical
타인생산 : letter_recv  media  about
생활기록 : photo  av  ephemera  object
한국특수 : genealogy  ritual
```

20종이면 UI에서 한 화면에 담기고, 이 이상 늘리면 아무도 정확히 고르지 않습니다.

## 4. 자동 추정과 수정

**필수 입력이 아닙니다.** 업로드 시 기본값을 자동으로 넣고, 사용자는 필요할 때만 바꿉니다.

| 조건 | 기본값 |
| --- | --- |
| 이미지 파일 | `photo` |
| 영상·음성 파일 | `av` |
| 데일리 인터뷰 녹음 | `interview` |
| 대화 녹음 업로드 | `oral_history` |
| 웹 UI 직접 작성 | `writing` |
| 텍스트 파일 | `writing` |

스캔한 편지를 올리면 처음엔 `photo`로 들어가지만, 사용자가 `letter_recv`로 고치면 됩니다. 상세 화면에서 언제든 수정 가능하며, 미수정 상태로 두어도 아카이브 기능에는 지장이 없습니다.

**입력 부담을 줄이는 장치**
- 같은 업로드 배치 내에서 한 번 고르면 나머지에 일괄 적용
- 최근 사용한 3개를 상단에 노출
- 컬렉션에 기본 `doc_type`을 지정해두면 그 컬렉션 업로드 시 자동 적용

---

## 5. 민감정보 처리

증빙 계열(B)은 주민등록번호·계좌번호·병력 등이 그대로 노출된 경우가 많습니다.

`doc_type`이 `vital` / `official` / `financial` / `medical` 중 하나로 지정되면:

1. 업로드 화면에 안내 표시 — "민감정보가 포함될 수 있습니다"
2. **`local_only` 기본값을 `TRUE`로 설정** — 외부 STT·캡셔닝 API로 전송 금지
3. 열람 권한을 관리자 계정으로 제한하는 옵션 제공
4. Export 시 기본 제외 (RAG 연표 생성에만 내부적으로 사용)

> 호적등본 이미지가 외부 API로 나가는 상황은 반드시 막아야 합니다.

## 6. Export 매핑

`doc_type`이 데이터셋 생성 로직을 직접 결정합니다.

| 데이터셋 | 포함 `doc_type` | 비고 |
| --- | --- | --- |
| **LLM 파인튜닝** | `diary` `letter_sent` `writing` `interview` `oral_history` | 자기표현 계열만. `creator_id`=대상자 조건 필수 |
| **음성 클로닝** | `interview` `oral_history` `av` | 화자 확정(`confirmed`)된 발화만 |
| **이미지 LoRA** | `photo` | 인물 태그 확정분만 |
| **RAG** | **전체** | 증빙 포함 — 연표 정확도 확보 |
| **생애 연표** | `vital` `education` `award` `official` | 날짜 확정 근거로 사용 |

**증빙 자료의 특별한 쓸모**
`vital`·`education` 자료에서 추출한 확정 날짜는 다른 기록의 `recorded_at` 추정 기준이 됩니다. "졸업장이 1957년이니 이 교복 사진은 1954~57년 사이"처럼요. 이를 위해 증빙 자료에서 뽑은 날짜를 별도로 기록합니다.

```sql
ALTER TABLE archive_items ADD COLUMN verified_date DATE;
-- 증빙 자료에서 확인된 확정 일자. 연표의 기준점이 된다.
```

## 7. 스키마 반영

```sql
ALTER TABLE archive_items
  ADD COLUMN doc_type      VARCHAR(20),   -- 3절 20종
  ADD COLUMN doc_type_by   VARCHAR(10) DEFAULT 'auto',  -- 'auto'(추정) | 'user'(확인)
  ADD COLUMN verified_date DATE;          -- 증빙 자료에서 확인된 확정 일자

CREATE INDEX ON archive_items (doc_type);
```

`doc_type_by`로 자동 추정과 사용자 확인을 구분합니다. `auto` 상태인 항목은 어드민에서 "분류 확인 대기" 목록으로 모아 일괄 정리할 수 있습니다.

## 8. 참고

- **DACS (Describing Archives: A Content Standard)** — 문헌형식(documentary form)을 별도 기술요소로 두고, 형식의 공통 속성으로 내용을 짐작하게 하는 개념. 용어는 AAT·LC Authorities 참조를 권고
- **국내 지역·공동체 아카이브 형태분류** — 문서류·사진류·도서간행물류·시청각류·박물류·구술류 (제주학아카이브, 공주학아카이브, 화성시민아카이브 등). 출처·주제·시기·형태를 각각 별도 축으로 운영
- **개인기록(personal papers) 유형 구분** — 서신, 일기, 학적, 금융, 신분증명, 간행물, 소품, 시청각 (미국 대학 아카이브 및 NARA 실무)
- 최유리·임진희, 「개인기록 관리 방안 연구」, 기록학연구 47, 2015 — 전자/비전자 구분, 실물가치(intrinsic value) 개념
- 류한조, 「개인 생애기억 아카이브를 이용한 개인서사 구성 연구」, 기록학연구 67, 2021 — 기록을 기억에 종속시키는 계층 구조
